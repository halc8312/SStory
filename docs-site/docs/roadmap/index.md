## Phase 3: インタラクティブ交通マップ v0.1 (v0.3)

**目標**: Webブラウザ上で nodes, routes, hazards を表示する。

### 機能

- [ ] Leaflet 導入
- [ ] nodes.json 読込み、地図上にマーカー表示
- [ ] routes.json 読込み、地図上にライン表示
- [ ] hazards.json 読込み、危険区域を色塗り表示
- [ ] クリックでノード詳細（名前、タイプ、人口など）をポップアップ表示
- [ ] レイヤー切り替え（nodes / routes / hazards の表示/非表示）
- [ ] 交通種別フィルタ（陸路・海路・空路）

### 技術

- 純粋な JavaScript (Vanilla JS or 軽量ライブラリ)
- Leaflet + CSS
- データは静的JSONを fetch

## Phase 4: Web版ルート検索 (v1.0)

**目標**: 出発地・目的地を選び、最適経路を表示する。

### 機能

- [ ] 出発地・目的地の選択UI（ドロップダウン or 地図クリック）
- [ ] 交通種別フィルタ（陸路/海路/空路/組み合わせ）
- [ ] ルート計算（Python版 route_finder.py のロジックを JavaScript 移植）
- [ ] 複数経路の提示（最短距離、最短時間、最安全）
- [ ] 季節運行判定（季節によって通行不可ルートを除外）
- [ ] 計算結果の地図上への描画（ライン強調表示）
- [ ] ルート詳細（距離、所要時間、通過ノード、危険区域）

### 移植元

`tools/map/route_finder.py` のアルゴリズム（Dijkstra, A*）をJavaScriptへ移植。

### 注意

- PythonはGitHub Pagesで実行不可 → クライアントサイドJavaScriptで実装
- 大規模データでもBrowser内でサクサク動くように最適化

## Phase 5: 地図画像オーバーレイ (v1.1)

**目標**: 生成された静的地図画像を背景として利用。

### 機能

- [ ] 世界地図画像（world-map.png）をベースレイヤーとして表示
- [ ] 大陸地図画像への切り替え
- [ ] 地図画像とMap Data（ノード・ルート）の位置合わせ（キャリブレーション）
- [ ] 地図画像のズーム・パン対応
- [ ] 透明度調整機能（地図画像とデータの重ね合わせ）

### 課題

- 地図画像の座標系（投影法）とGeoJSONのWGS84座標の整合性を確保
- 必要に応じて、地図画像作成時にGeoJSONを参照して正確な位置に描画

## 依存関係

各フェーズは**依存関係**があります：

```
Phase 1 (v0.1) → 必須 → Phase 2 (v0.2) → Phase 3 (v0.3)
                                         ↓
                                  Phase 4 (v1.0)
                                         ↓
                                  Phase 5 (v1.1)
                                         ↓
                                  Phase 6 (v1.2)
                                         ↓
                                  Phase 7 (v2.0)
```

- Phase 3 は Phase 2 に依存（既存データが整理されていないと表示コンテンツ不足）
- Phase 4 は Phase 3 に依存（地図表示が前提）
- Phase 5 は Phase 3 に依存（地図ビューアが必要）
- Phase 6 は Phase 5 に依存（画像オーバーレイ技術が必要）
- Phase 7 は Phase 2 に依存（全データが整理されている必要）

## リスクと対策

### 技術リスク

| リスク | 影響 | 対策 |
|--------|------|------|
| Leaflet の学習コスト | 中 | チュートリアルから開始、プロトタイプ作成 |
| データ量増大による遅延 | 中 | クラスタリング、Lazy Load |
| 座標系の不整合 | 高 | 早期にテストデータで検証 |
| モバイル対応 | 中 | レスポンシブデザイン、タッチ操作対応 |

### 運営リスク

| リスク | 影響 | 対策 |
|--------|------|------|
| メンテナーの時間不足 | 高 | コントリビューター募集、Issue/TODOの明確化 |
| データの不整合 | 中 | CI自動検証、スキーマバリデーション |
| ライセンス問題 | 低 | CC BY-SA 4.0 の明記、third-party assets の確認 |

## 貢献方法

このロードマップの各項目は、**別々のIssueとして分割**してコントリビュート可能です。

### コントリビューション例

1. **ドキュメント改善**: 各ページの内容充実
2. **データ追加**: `world/map-data/data/` にノード・ルート追加
3. **テスト**: 既存Pythonツールのテストケース追加
4. **デザイン**: CSS の改善、モバイル対応
5. **Webマップ実装**: v0.3 以降のJavaScript実装

### 作業開始手順

1. Issue を確認（本サイトと関連Issue）
2. ローカルで `mkdocs serve` してサイトを起動
3. 変更を加え、`mkdocs build` でビルド確認
4. PR作成
